# GeoFiles 功能实施计划（Mirroxy 0.6.1）

## 背景与现状

Mirroxy 的分流规则依赖 14 个 geo 资产文件，位于 `<安装目录>/bin/resources/`（xray 用 `Mirroxy_route_ip.bin`/`Mirroxy_route_domain.bin` 即 geoip.dat/geosite.dat；sing-box 用 `Mirroxy_set_01..12.bin` 即 .srs 规则集，映射见 `routing.go:49-58`）。目前它们只是构建时的固定快照，没有版本跟踪、没有更新入口。本功能新增「GeoFiles」：面板内查看每个规则文件的状态并一键更新。

**数据源（已逐一验证可达）：**
- xray 两个 dat：`Loyalsoldier/v2ray-rules-dat` latest release 的 `geoip.dat`/`geosite.dat`（tag 为日期式版本如 `202609290124`，且提供 `.sha256sum` 校验）。
- sing-box 12 个 .srs：`MetaCubeX/meta-rules-dat` 的 `sing` 分支 `geo/geoip/<类>.srs` 与 `geo/geosite/<类>.srs`（SagerNet 官方 release 只有聚合 .db、无按类别 .srs，故采用与 v2rayN 同源的 MetaCubeX 类别文件）。12 个类别与现有 `Mirroxy_set_XX.bin` 一一对应：geoip-cn、geosite-cn、geosite-private、geosite-gfw、geosite-greatfire、geosite-google、geoip-facebook、geoip-fastly、geoip-google、geoip-netflix、geoip-telegram、geoip-twitter。若个别类别文件缺失，只报该文件错误、不影响其他文件。
- 下载统一走现有 `a.fetch`（update.go:76），自动按「存活节点本地端口 → 系统回环代理 → 直连」回退，国内环境无需额外镜像。

## 后端（新文件 `geofiles.go`）

1. **目录表** `geoCatalog`：14 条记录（规则名、资产文件名、引擎 xray/sing-box、用途说明、下载 URL、版本类型 release/date）。
2. **状态** `geoFilesState()`：每文件返回 `{name, engine, asset, exists, size, updatedAt(文件 mtime), version(cfg.Updated["geo:"+name]), used(按当前全局/节点路由模式判断是否被引用)}`。`state()`（api.go:51）新增 `"geoFiles"` 字段，settings 部分新增 `geoAutoUpdate`。
3. **检查远程版本** `checkGeoFiles()`：GitHub API 查 Loyalsoldier latest tag（dat 组的远程版本）；.srs 来源无版本号，只能显示本机更新时间。
4. **更新** `updateGeoFiles(names)`，流程对齐 `updateCore`（update.go:186）：
   - `healthGate.Lock()` + `busyUpdate` 互斥（与核心更新/订阅刷新互斥）。
   - 逐文件 `a.fetch` 下载 → dat 用 `.sha256sum` 校验；srs 用内置 sing-box 校验格式（`rule-set decompile`，不可用则 `check` 探针配置）；核心程序缺失时跳过校验只做大小下限。
   - 换文件：写 `<asset>.next` → `stopEngine` 受影响引擎（xray dat / sing-box srs）→ 旧文件改名 `.previous` → 新文件就位 → `reconcileEngine`；任一步失败回滚旧文件并恢复。**事件与 UI 均注明「更新会短暂重启对应内核」**。
   - 成功后记录 `cfg.Updated["geo:"+name]`（dat 记 release tag，srs 记更新时间戳）并 `a.save()`、写事件日志。
5. **API**（api.go，与 core/update 同一 switch，远程访问可用）：
   - `POST /api/geofiles/check` → `{"version": tag}`
   - `POST /api/geofiles/update` body `{"files": [...]}`（空缺省=全部）→ 同步执行，成功 `{"ok":true}`，失败 400 中文错误。
6. **设置与自动更新**：`Settings` 增加 `GeoAutoUpdate bool`（默认 false，load() 补默认值），`SettingsPatch` 增加 `GeoAutoUpdate *bool`。`maintenance()`（main.go:292）比照「每日自动更新核心」增加 24h 分支调用 `updateGeoFiles`（全部文件；busy 时本轮跳过，失败写事件）。

## 前端（web/）

1. **index.html**：
   - 设置子导航（:27）加 `<button data-settings-view="geofiles">Geo 文件</button>`；新增 `<section id="view-geofiles">`：页头（标题「Geo 规则文件」+「更新全部」主按钮）+ 两张 settings-card：「Xray 路由数据库」（2 个 dat，含"检查远程版本"按钮）与「sing-box 规则集」（12 个 .srs），容器由 JS 渲染，复用 `core-grid`/`core-card` 样式，不加新 CSS。
   - 设置页「更新」卡（:43）加「每日自动更新 Geo 规则文件」开关 `settingGeoUpdate`（默认关）。
2. **app.js**：`view()` 的 `settingsView` 数组与 `pageName` 加 `geofiles`；新增 `renderGeoFiles()`（挂入 `render()`）：显示每文件名称/用途/状态（缺失标红并提示可更新修复）/大小/更新时间/版本，按钮 `data-geo-check`、`data-geo-update`、`data-geo-update-all` 走现有 `act()`+`api()` 委托；settings 读写绑定 `geoAutoUpdate`。
3. **i18n.js**：补齐新字符串的 en 词条；changelog 渲染不变。
