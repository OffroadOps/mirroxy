# 服务器与节点能力探测

应用代理是否适合游戏，不能只看 Xray 或 sing-box 的版本。结果至少由三层共同决定：服务器主机出口、服务端协议配置、客户端到节点的完整链路。

## 服务器主机探测

在 Linux 服务器上运行：

```bash
Mirroxy -probe-server
```

命令只进行出站连接并输出 JSON，不写配置、不开放端口、不修改防火墙。它检测：

- IPv4 TCP 出站；
- IPv4 UDP 出站和 STUN 观察到的出口地址；
- IPv6 TCP 出站；
- 对两个 STUN 目标端口的 UDP 映射是否一致；
- 当前目录中的 Xray / sing-box 版本。

`endpoint-independent` 表示对两个目标端口观察到相同映射，通常更适合点对点和游戏 UDP；`symmetric-likely` 表示映射随目标变化，属于对称型倾向；`unknown` 表示证据不足。它不是主机厂商所称的 NAT1–4，也不能证明服务端协议已允许 UDP。

## 客户端完整链路探测

Windows 面板「游戏 / 应用代理」中的“检测默认节点”会经过节点的强制全局内部入口，实际测试：

- SOCKS5 TCP CONNECT；
- SOCKS5 UDP ASSOCIATE + STUN；
- 代理服务端访问 IPv6 目标；
- UDP 映射稳定性。

服务器主机检测通过、客户端节点检测失败，通常说明问题位于协议配置、防火墙、服务端核心或中间网络。客户端检测通过才是该节点能用于应用代理的主要依据。

STUN 使用 Cloudflare 公共服务的 UDP 3478 和备用 UDP 53。检测结果是一次网络快照；运营商、机房路由或服务器配置改变后需要重新检测。
