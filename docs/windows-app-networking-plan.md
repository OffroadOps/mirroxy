# Windows 应用代理、TUN 与固定出口方案

日期：2026-09-07。状态：0.6.0 开发实现已加入，尚未发布。

## 0.6.0 当前实现边界

- 已新增网页「游戏 / 应用代理」、运行进程选择、目录扫描选择程序（最多 3 层子目录，主程序自动识别）、每应用节点覆盖、节点行「指定应用」入口、默认应用节点和 Windows UAC 助手。
- 选中程序的 TCP/UDP 通过 sing-box TUN 按进程匹配，再进入节点专用的认证回环端口；这个入口按该节点的出口策略分流（如绕过大陆：大陆与局域网直连，其余经节点），「全部走此节点」模式保持全量经节点。本机与局域网地址始终直连。
- 未选程序最终直连；本机和局域网地址优先直连。TUN 默认关闭，关闭状态不会改路由、系统代理或启动管理员进程。
- 与网易 UU、雷神等 TUN 类游戏加速器无法真正共存：两者都做全局路由接管。开启应用代理前会检测已知加速器进程（UU、雷神、迅游、奇游、Biubiu、OurPlay）并提示冲突；「加速器兼容模式」关闭 strict_route 以降低防火墙互拦，属缓解而非共存方案。加速器正在加速的游戏不要同时加入应用绑定。
- 已增加从客户端真实穿过节点的 TCP、UDP、IPv6、STUN 映射检测，以及 `-probe-server` 服务器主机只读探测。
- 当前版本没有宣称实现 WFP 持久化断网保护。节点进程短暂失败时，应用专用 SOCKS 出口会失败而不会回退；若整个 TUN 助手被强杀，Windows 可能恢复普通直连。下文的 WFP 严格保护仍属于后续阶段。

## 目标与界面

- 左侧增加「游戏 / 应用代理」：应用列表、运行进程选择、默认节点、按应用覆盖节点和能力检测。
- 页面提供独立的应用代理开关。Mirroxy 后台继续以普通用户运行，仅开启 TUN 的隐藏助手请求管理员权限；TUN 初始关闭，系统代理仍默认「不改变」，保持与现有 v2rayN 的使用习惯兼容。
- 固定代理按「选择应用 → 选择节点 → 启用失效断网」配置。绑定稳定节点 ID，不绑定显示名称或当前系统代理选择。
- 展示三类状态：未保护、已锁定节点、已阻断（节点离线或保护链路未就绪）。核心分流成功不能单独作为“已保护”的依据。

## 1. 图中的 AppContainer 功能

这是 Windows AppContainer 本地回环访问豁免，解决应用不能连接 127.0.0.1 本地服务的问题。它不决定出口节点，也不保证应用遵守系统代理。

使用 Windows 自带 Firewallapi.dll 的 NetworkIsolationEnumAppContainers、NetworkIsolationGetAppContainerConfig 和 NetworkIsolationSetAppContainerConfig；Go 可直接调用，不依赖 .NET 或外部 GUI 工具。写入前重新读取并合并已有 SID，只修改用户指定的项目，保留 v2rayN 等软件已配置的豁免。逐项与批量修改应明确覆盖范围；撤销只还原本软件管理的变更。

本机只读枚举成功，返回 98 个 AppContainer；未改变豁免设置。

官方依据：[Microsoft AppContainer 配置 API](https://learn.microsoft.com/en-us/windows/win32/api/netfw/nf-netfw-networkisolationsetappcontainerconfig)。

## 2. TUN 的接入方式

现有 sing-box 作为 TUN 入口，继续复用 Xray / sing-box 节点出站。当前 TUN 同时声明 IPv4、IPv6 地址，DNS 保持 Windows 当前设置且不做全机劫持，以免改变未选应用；后台拥有生命周期管理，启动失败则恢复本次修改的网络状态。需要严格限制共享系统 DNS、应用崩溃后仍阻断直连时，仍要完成下文的 WFP 阶段，不能把当前实现冒充为持久化防泄漏。

现有 coreConfig 按本地端口生成规则，bypass-cn 和 blacklist 可以返回 direct。因此固定应用不能简单转发到一个仍会绕过大陆的普通 506x 端口。应增加内部专用入口，强制映射到绑定节点；或者在兼容的核心内直接使用绑定节点的出站。固定规则优先于全局绕过规则。专用入口不使用 URLTest、备用节点或 DIRECT 回退。

普通流量仍由全局路由模式控制。核心连接应绑定真实出口网卡或使用自动检测机制，避免被自己的 TUN 再次接管。处理并存的 v2rayN 时，要识别实际进程与出口，不能把所有同名代理核心全部直接放行。

DNS、UDP/QUIC、IPv6 都纳入设计；不支持的流量明确拒绝。TUN strict_route 能加强路由和 DNS 约束，但不能替代应用级断网保护。

本机现有 sing-box 1.13.16 和完整发行包中的 1.14.0 均通过了合成 TUN + process_path 规则的 `check`。仅验证语法，未创建虚拟网卡或验证转发。

官方依据：[sing-box TUN](https://sing-box.sagernet.org/configuration/inbound/tun/)、[进程路径规则](https://sing-box.sagernet.org/configuration/route/rule/#process_path)。注意 package_name 是 Android 包名匹配，不能用于 Windows 包身份。

## 3. 固定代理与断网保护

预期行为：Claude 只能通过所选节点联网；用户切换普通系统代理或其他节点不影响绑定。节点失败、被停止、TUN 崩溃、Mirroxy 退出或更新重启期间，受保护应用仍保持阻断。节点恢复并验证保护链路就绪后，恢复同一节点。正常退出软件不自动解除绑定；需要独立的本机解除入口及管理员恢复命令。

实现分成两层：

1. 流量选择：按应用可执行路径、Windows 包身份及实际联网子进程识别目标，转入固定节点。避免仅匹配 `Claude.exe` 名称，也避免把所有共享 WebView2 进程归为 Claude。
2. 系统保护：使用 Windows Filtering Platform 对目标身份设置持久化阻断，限制直连和其他本地代理通道；只允许已验证的专用代理通道或受控 TUN 路径。保护策略先安装、后允许目标应用联网。退出或崩溃不能自动删除阻断规则。

WFP 的动态会话在拥有者退出时删除规则，不适合作为这层保护。持久化规则及启动期间的衔接需要单独设计和验证；规则生命周期不能依附于 TUN 核心进程。不能用“每 60 秒检测失败后再断网”代替底层保护，也不能简单组合 Windows 防火墙“全阻止 + 一条允许”而忽略规则优先级。

关键兼容点：目标应用若先连接 v2rayN 的 127.0.0.1:10808，之后外连的是 v2rayN，TUN 仅按原应用进程分流可能无法识别。固定模式必须控制目标应用的本地代理去向；可先支持显式使用专用代理的应用，忽略代理设置的连接由保护规则阻断。对必须透明重定向的应用，需要进一步验证重定向机制，不能把普通进程路由当作完整替代。

启用绑定前需处理已有连接：受控重启应用或可靠终止旧流。绑定不能在应用更新更换路径后悄悄失效；先支持可明确识别身份与联网进程的桌面应用，更新时原子地迁移保护规则。浏览器和共享网络代理进程需独立适配。

绑定节点被删除、缺少核心、端口冲突或规则安装失败时均保持阻断，并在面板显示原因。更改绑定只由用户明确操作。订阅刷新保留同一逻辑节点绑定；节点消失时不得自动匹配其他节点。

“固定节点”无法保证服务商不改变节点的实际出口 IP，也不等于保证第三方账号不会触发风控。可显示观察到的出口 IP；IP 检测只能作为附加状态，不能代替网络层约束。

官方依据：[WFP 规则生命周期](https://learn.microsoft.com/en-us/windows/win32/fwp/object-management)、[Microsoft WFP 各层匹配条件](https://github.com/MicrosoftDocs/win32/blob/docs/desktop-src/FWP/filtering-conditions-available-at-each-filtering-layer.md)。以上为据此拟定的工程方案，严格断网效果尚待实际故障测试。

## 权限、升级与兼容

Windows 后台正常启动时请求 UAC；未获管理员权限不假装 TUN 已启用。`-version`、离线检查等无副作用命令不应强制提升，以兼容现有在线更新预检。现有非管理员 0.4.4 向新版本升级，需显式处理一次权限提升和回滚；不能只增加 requireAdministrator manifest，导致旧更新助手无法运行候选版本。

系统级操作限定为结构化的应用/节点 ID，不能从 Web 面板传任意命令。保持远程认证、本机来源校验，管理员服务只接受必要操作。跨平台构建保留，Windows 专用项在其他平台显示不支持；不宣称 Linux/macOS 已获得相同应用断网保护。

## 验收顺序

1. 隔离验证 AppContainer 枚举、现有豁免保留、指定项增删与恢复。
2. Windows 测试环境验证 TUN 启停、DNS、IPv4/IPv6、UDP、路由恢复及与 v2rayN 并存。
3. 明确 Claude 客户端版本、安装形态、实际联网进程和升级方式；验证绑定后出口。
4. 连续请求期间切换其他节点、停止固定节点、强杀核心和主程序、在线更新、重启系统、切换网卡、断网重连。通过服务器记录或抓包确认受保护流量未出现其他出口。
5. 验证目标应用已有连接、应用更新、其他本地代理、子进程、DNS/IPv6/QUIC 和解除保护恢复流程。
6. 实证通过后才将严格保护标为可用，新增版本更新日志并按四平台流程发布。

当前已完成单元测试、竞态检测、四平台交叉编译，以及使用已安装 Xray 26.7.28 / sing-box 1.14.0 的配置校验；尚未执行会创建虚拟网卡的 Windows 实机转发测试。当前正式发布仍为 0.5.2，本方案不代表新功能已经上线。
